# tools/render/

The offline music render harness (Electron based). Author tooling, never
shipped: `electron-builder`'s packaged files list does not include `tools/`.
Driven by `npm run audio:music`, which renders then encodes. Reads the
composition sources in `js/music/src/` and writes `.webm` stems into
`assets/music/`. No README lives in this folder; this master and the header
comment of each file below are the documentation.

- `.gitignore`: ignores `out/`, the build staging directory (WAVs, the render
  cache, the render log, the sample count sidecar), all regenerated by
  `npm run audio:music`.

- `encode.cjs`: the encode half of the harness, `node tools/render/encode.cjs`
  (also runs as the second step of `npm run audio:music`). Takes the WAVs
  staged in `out/` and writes the files the game actually ships:
  `assets/music/<theme>_<layer>.<hash8>.webm`, Opus in WebM, via `ffmpeg` on
  PATH. Also writes `out/samplecounts.json`, the exact source sample count
  per loop, since a lossy encode cannot recover that afterwards and the game
  needs it to loop the stems sample accurately. Flags: `--only <theme>`,
  `--dry-run`, `--force`.

- `fakeaudio.cjs`: a fake Web Audio graph for testing compositions in plain
  Node, used by `selftest.cjs`. Produces no sound; catches what would
  otherwise only show up as a red line in the render page itself: a missing
  helper, a mistyped note name, a NaN where a time should be, an exponential
  ramp to zero (real Web Audio throws on that), a stop before a start.

- `index.html`: the hidden Electron render page. Never shown to a user; it
  exists because Chromium's Web Audio implementation is the actual renderer,
  so an `OfflineAudioContext` here bakes the same graph the game plays live.
  Loads `wav.js`, `stems.js`, `renderer.js` in that order.

- `main.cjs`: the Electron main process and the entry point,
  `npx electron tools/render`. Opens the hidden page, hands it the
  composition sources from `js/music/src/` (via `js/music/src/index.js`'s
  `MBM_MUSIC_SOURCES` list), and receives finished WAVs over IPC into
  `out/`. Flags: `--only <theme>[,<theme>...]`, `--force`. Nothing is written
  anywhere outside `tools/render/out/`.

- `package.json`: names this folder `mbm-render` for Electron's benefit
  (`main: main.cjs`) so `npx electron tools/render` resolves. Not an
  npm workspace; nothing installs from it beyond what Electron itself needs.

- `preload.cjs`: the only bridge between the sandboxed render page and disk.
  Exposes `window.mbmRender` with `job()`, `write(name, uint8)`, `log(line)`,
  `done(summary)`, `fail(message)`. `main.cjs` alone decides where a file
  lands and refuses any name that is not a plain filename directly inside
  `tools/render/out/`.

- `renderer.js`: runs inside the hidden page. Loads every composition source
  from `js/music/src/`, renders each layer of each theme through its own
  `OfflineAudioContext`, folds the reverb tail back onto the head so the loop
  is seamless, asserts every layer of a theme is exactly the same sample
  length, and hands the finished 16 bit WAVs back through `window.mbmRender`.
  Touches disk through no path other than that bridge.

- `selftest.cjs`: `node tools/render/selftest.cjs` (also `npm run
  audio:music:test`). Pure logic tests with no Electron, no Web Audio, no
  ffmpeg: the WAV writer, the loop length rules, the tail fold, the sample
  count assertion, and the ffmpeg argument list. Cannot test the audio
  itself, since that needs Chromium; that is what `npm run audio:music` is
  for.

- `stems.js`: the stem length rules, loaded both as a classic script inside
  the render page and as a CommonJS module by `selftest.cjs`. No Web Audio
  API calls in it on purpose, so all of it is testable in plain Node. Why it
  matters: the game crossfades a theme's layers against each other, and a one
  sample length mismatch drifts further apart on every loop, so the loop
  length is computed once per theme here and every layer is held to it
  exactly.

- `wav.js`: 16 bit WAV writer and reader, loaded both as a classic script
  inside the render page and as a CommonJS module by `encode.cjs` and
  `selftest.cjs`. Dependency free by design, since both entry points need it
  to keep working. Its dither is a seeded mulberry32 RNG, not `Math.random`,
  so repeat renders of unchanged source produce byte identical WAVs and the
  render cache can trust that.
